Know what’s known.区分已知与未知。

Explore monitoring rules查看监测规则↗

Explicit inputs. Honest limits.明确来源，如实呈现边界。

Bind a permitted log to one session and working directory. Cumulative tokens, cached tokens, and context occupancy remain separate. Suggestions carry their rules and evidence.将有权限读取的日志绑定到准确会话及工作目录。累计 token、缓存 token 与上下文占用分别处理，建议附带规则及依据。

A checkpoint, not a verdict.提供检查点，不轻率下结论。

High occupancy does not prove declining quality. Monitoring never creates a session on its own, invents a health score, or renders custom output inside Codex’s native statusline.高占用不代表质量下降。监测不会自行创建会话，不编造健康分，也不会将自定义输出插入 Codex 原生状态栏。

◇

Built with boundaries.清晰的边界，
可核查的交接。

Local task records本地保存任务材料

State lives under $XDG_STATE_HOME/auto-handoff, or ~/.local/state/auto-handoff. Keep credentials and unrelated personal data out of packets. Real handoffs send task content through your configured Codex model service and may incur usage.状态保存在 $XDG_STATE_HOME/auto-handoff，或 ~/.local/state/auto-handoff。不要加入凭据或无关个人信息。真实交接会通过你的 Codex 模型服务处理任务材料，并可能产生用量。

Careful recovery谨慎恢复，避免重复

The original session and uncommitted changes remain. Reuse the operation ID when retrying. If a result is uncertain or a new ID already exists, inspect the record before creating another session.保留原会话及未提交改动。重试时复用 operation ID；结果不确定或已有新 ID 时，先核对记录，不要盲目再建会话。
